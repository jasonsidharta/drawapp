## Traced: a pencil and an ink preset

**PhotoCraft "Soft Pencil"** (`presets.rs`):
- **Settings:** size 6, hardness 0.6, spacing 0.08. Shape Dynamics size on pressure, minimum 0.4. Transfer opacity on pressure, minimum 0.15. Procedural "Paper" texture at scale 0.5, depth 0.8, Multiply.
- **Input dynamics** (`dynamics.rs`): `PathWalker` places steps every `diameter × spacing` px, interpolating position, pressure, tilt and time linearly between input points; the "next step at" distance carries across segments. `base_diameter` = size × (min + (1 − min) × pressure). In `DabBuilder::build`, `alpha` = flow and `opacity` = the transfer-opacity scalar, which is the per-dab **ceiling**.
- **Rasterising** (`render.rs`): `rasterize_round`. Inside `hardness × r` coverage is 1; outside it falls off as `(1 − t²)⁴` times an anti-aliased edge `clamp(r + 0.5 − d)`. Tips under a 3 px radius use 4 × 4 subsamples per pixel, because sampling only pixel centres made thin lines bead.
- **Accumulating** (`CoverageMap::accumulate`): a sparse 64² float coverage map, updated per dab as `c ← c + v·(ceiling − c)`, where `v` = tip × flow.
- **Compositing:** the texture is a stroke-level mask in document space (coherent along the stroke). `k = mask(c) × stroke opacity × selection`, composited source-over onto the **pre-stroke** pixels, so a stroke can be recomposited incrementally. 8-bit results get a position-hashed dither of under half a level: exact levels stay exact, gradients don't band.

**PhotoCraft "Ink Pen":** hard round 8 px, spacing 0.05, size on pressure with minimum 0.15, smoothing 0.35. Same pipeline, no texture.

**Krita "Pencil-2"** (data only): paintbrush op; a 10 px Gaussian tip (fade 0.15, no anti-aliasing); spacing 0.2; size on pressure with curve `0,0.49 → 1,1`; opacity on pressure with an S curve `0,0; 0.13,0.10; 0.47,0.71; 1,1`; no texture. The pencil character comes from the pressure curves on a slightly soft tip.

**Krita "Ink-3 Gpen":** hard anti-aliased circle, 5 px default, auto-spacing 0.2, flow 0.6, size curve from 7 % at zero pressure, opacity curve flat at 1.

**Krita "Airbrush Soft":** a 600 px soft tip with a custom softness curve, spacing 0.1, airbrushing at rate 1000, opacity on pressure.

## Opacity, flow and build-up in the references

- **PhotoCraft:** stroke opacity is applied once at compositing. Flow builds coverage towards a per-dab ceiling (transfer opacity). With flow 1 and a hard tip, overlapping dabs equal the ceiling, so opacity is uniform.
- **Airbrush** (`build_up`): time-based steps at `build_up_rate` per second from point **timestamps** (`PathWalker`, `interval`), capped per segment; stalled timestamps don't replay a backlog.
- **libmypaint** names the density problem directly: `opaque_linearize` corrects "the nonlinearity introduced by blending multiple dabs on top of each other". Without it, a pass's darkness depends on how many dabs land on a pixel, which spacing determines.
- **Krita** offers build-up (incremental) and wash (indirect painting with alpha darken) per preset (see `krita-android-saving-stylus-brush.md`).

## Smudge in the references

| Reference | Model | Transparency |
|---|---|---|
| PhotoCraft Smudge (`retouch.rs`) | A carried colour **patch** centred on the dab. Each dab lays the patch down at `strength`, then picks up the pixels under it (the patch keeps `strength` of itself). Dabs work sequentially on a working copy | Mixed in **premultiplied** space, so the colour of transparent pixels never leaks; a test checks for no dark fringe when smudging into transparency |
| PhotoCraft Mixer Brush (`mixer.rs`) | A reservoir colour and a pickup colour (alpha-weighted average under the dab); deposits a mix at flow | Deposits opaque colour: transparency is not carried |
| libmypaint | One averaged colour per stroke (or per "bucket"), refreshed at a rate (`smudge_length`); the dab colour lerps towards it | `apply_smudge` returns an "eraser target alpha": smudging transparency into paint **erases towards it**. `smudge_transparency` can refuse to pick up below an alpha |
| Krita colorsmudge | Smearing mode copies pixels from the previous dab position (smear op, opacity = smudge rate); dulling mode uses a weighted average colour. A colour rate mixes in the brush colour | Copy-style smearing carries alpha |

## What we need to implement

1. A brush **settings model** separate from `CanvasItem`: tip (round or sampled), hardness, spacing,
   opacity, flow, accumulation mode, pressure → size / opacity / flow mappings, texture (id, scale,
   strength, mode), airbrush rate, smudge parameters, tilt use, smoothing default. JSON with a
   version and validation.
2. **Float coverage** (8-bit stalls at small per-dab increments) and **two explicit accumulation
   modes**: *uniform* (maximum, today's behaviour) and *build-up* (`c ← c + f·(ceiling − c)`).
   Build-up flow is normalised by dab density so that "flow" means the coverage of one pass,
   independent of spacing (our answer to `opaque_linearize`).
3. **Time-based airbrush dabs** from sample timestamps, plus a time source while the pen is held
   still.
4. **Sampled grayscale tips** with mip levels, a falloff for soft round tips, and area-sampled tiny
   tips.
5. A **document-space texture** applied at compositing (Multiply, or Subtract for a pencil "tooth"
   that light pressure leaves in the valleys).
6. **Dither** when quantising a fractional stroke alpha to 8 bits (soft airbrush bands otherwise),
   keeping exact levels exact.
7. **Smudge**: a premultiplied carried patch with strength and pickup, on the active layer only.
8. Deterministic per-stroke randomness (seeded hash) for jitter; tilt → angle and size when the
   device reports tilt.
9. Presets, a preset store, and UI with real rendered thumbnails and a scratchpad.

## Tradeoffs and known limitations

- **Coverage buffer vs direct stamping.** Accumulating into a per-stroke buffer and recompositing
  from the pre-stroke tiles costs one extra pass per touched tile per event, but gives
  uniform/build-up control, stroke-level texture and exact undo. Dab stamping straight into the
  layer would be simpler, but cannot keep opacity uniform within a stroke.
- **Smudge is sequential**: each dab reads the result of the previous one. It therefore bypasses
  the coverage buffer and edits the layer directly, captured into the undo tiles first. It is
  blending, not a paint simulation: no wet layer, no pigment mixing.
- **Resampling.** Interpolating linearly between input samples preserves the drawn polyline
  exactly, whatever the event rate. It cannot recover curvature that sparse samples never saw: a
  fast curve reported by 3 events becomes 3 straight segments. Smoothing rounds such corners
  only by its string length. Identical output is only claimed for input describing the same
  polyline.
- **Texture in document space** stays coherent along and across strokes, but does not rotate with
  the canvas view (there is no view rotation yet) and repeats with its tile period (256 px at
  scale 1).
- **What we deliberately leave out:** dual brush, scattering, colour dynamics, wet edges, mixer
  reservoirs, symmetry, brush import (`.abr`, `.kpp`, `.myb`), and pigment simulation.
